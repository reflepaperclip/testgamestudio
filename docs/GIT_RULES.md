# Git 규칙

이 저장소에서 일하는 모든 에이전트와 사람은 아래 규칙을 따른다.

## 브랜치
- `main`은 항상 열어서 실행할 수 있는 상태로 유지한다. `main`에 직접 커밋하지 않는다.
- 작업은 이슈마다 브랜치를 만들어 한다. 이름은 `<유형>/<이슈ID>-<짧은-영문-설명>`이다.
  - 예: `feat/REF-12-player-move`, `art/REF-20-hero-model`, `fix/REF-31-save-crash`
- 유형: `feat`(기능), `fix`(버그), `art`(그래픽/모델), `audio`, `level`, `ui`, `refactor`, `docs`, `test`, `chore`

## 시작 전
1. `git status`로 작업 트리가 깨끗한지 확인한다. 남의 변경이 있으면 건드리지 말고 보고한다.
2. `git switch main` → `git pull --ff-only origin main`으로 최신화한다.
3. `git switch -c <브랜치>`로 작업 브랜치를 만든다.

## 커밋
- 한 커밋은 한 가지 목적만 담고, 자주 작게 커밋한다.
- 메시지는 한국어로 쓴다. 형식: `<유형>: <50자 이내 요약>` (본문에 이슈 ID와 이유를 적는다).
  - 예: `feat: 플레이어 이동과 점프 추가` / 본문 `REF-12`
- 빌드나 실행이 깨지는 상태로 커밋하지 않는다. 가능하면 Godot에서 열어 오류가 없는지 확인한다.

## 푸시와 병합
- 작업 브랜치만 푸시한다: `git push -u origin <브랜치>`
- `main` 병합은 풀 리퀘스트로 한다. 리드 프로그래머 또는 테크니컬 디렉터의 승인 후 병합한다.
- `git push --force`, `git reset --hard`, 남의 브랜치 리베이스, `main` 이력 수정은 금지한다.
- 충돌이 나면 임의로 한쪽을 덮어쓰지 말고 이슈에 상황을 적고 보고한다.

## Godot / Blender 파일
- `.godot/` 폴더와 `*.blend1` 백업은 커밋하지 않는다(`.gitignore`에 있음).
- 씬(`.tscn`)과 리소스(`.tres`)는 한 번에 한 사람이 수정한다. 같은 씬을 동시에 고치지 않는다.
- 큰 바이너리(원본 `.blend`, 대용량 텍스처/오디오)는 100MB를 넘기지 않는다. 넘을 때는 Git LFS 사용을 먼저 상의한다.
- 에셋은 `assets/<종류>/`, 스크립트는 `scripts/`, 씬은 `scenes/` 아래에 둔다.

## 비밀값
- 토큰, 비밀번호, API 키, `.env`는 커밋하지 않는다. 실수로 올렸다면 즉시 보고한다.

## 이슈 마무리
- 작업을 끝내면 이슈에 브랜치 이름, 커밋 해시(또는 풀 리퀘스트 링크), 변경 요약을 댓글로 남긴다.
